- ชื่อและกรอบงบ 5 ปีอ้างร่างเดิม ส่วนจำนวนหน่วย ราคาต้นทุน และกรณีอภิปรายเป็นตัวอย่างสมมติที่ต้องปรับก่อนใช้
- กรอบงบเพิ่ม 5 ปีเดิมยังรวม 190–310 ล้านบาท ตัวอย่างต้นทุนทดลองทั้งหกกรณีรวม 6,300,000 บาท ไม่ใช่งบเพิ่มอีกชุด และไม่ครอบคลุมต้นทุนทั้งจังหวัด

เว็บไซต์นี้เป็นแหล่งเรียนรู้ส่วนบุคคล ไม่ใช่เว็บไซต์ทางราชการ เนื้อหายุทธศาสตร์ พ.ศ. 2571–2575 และค่าเป้าหมายยังเป็นร่าง/ข้อเสนอ ไม่ใช่มติรับรองของจังหวัด ข้อมูลในชุดเอกสารตัดยอด 31 สิงหาคม 2569

## เริ่มใช้งาน

แตกไฟล์ ZIP แล้วเปิด `index.html` เพื่ออ่านเว็บไซต์บนเครื่องได้ทันที หน้าที่เชื่อมกันใช้ตำแหน่งไฟล์แบบสัมพัทธ์ จึงรองรับการนำขึ้น GitHub Pages ทั้งในโดเมนหลักและโฟลเดอร์ชื่อคลังงาน โดยไม่ต้องแก้เส้นทางไฟล์ทีละหน้า

ไม่ต้องติดตั้งฐานข้อมูล ไม่ต้องสมัครบริการแบบฟอร์ม ไม่ต้องมีรหัสลับ และไม่ต้องสั่งสร้างเว็บไซต์ก่อนอัปโหลด ผลประเมินที่บันทึกเมื่อเปิดไฟล์บนเครื่องอาจทำงานต่างกันตามเบราว์เซอร์ ให้ทดสอบการบันทึกบน URL ที่เผยแพร่จริงด้วย

## นำขึ้น GitHub Pages

1. สร้างคลังงาน (Repository — รีโพซิทอรี) ในบัญชี GitHub ของคุณ เช่น `ayutthaya-education` เลือกการมองเห็นตามสิทธิของบัญชี; บัญชี GitHub Free ใช้คลังสาธารณะสำหรับ Pages
2. อัปโหลด **ไฟล์และโฟลเดอร์ภายใน** `ayutthaya-education-site` ไปไว้ที่ระดับบนสุดของคลังงาน ไม่ใช่อัปโหลดไฟล์ ZIP หรือซ้อนทั้งโฟลเดอร์อีกชั้น `index.html` ต้องอยู่ระดับเดียวกับ `assets`, `articles` และ `downloads`
3. ตรวจว่ามีไฟล์ชื่อ `.nojekyll` อยู่ระดับเดียวกับ `index.html` หากเครื่องซ่อนไฟล์นี้ ให้ใช้เมนูสร้างไฟล์ของ GitHub ตั้งชื่อ `.nojekyll` และใส่ข้อความหนึ่งบรรทัดว่า `Static website` ได้
4. เปิด **Settings → Pages → Build and deployment** เลือก **Deploy from a branch** แล้วเลือกสาขา `main` และโฟลเดอร์ `/(root)` จากนั้นกด **Save**
5. รอ GitHub เผยแพร่สำเร็จ แล้วเปิด URL ที่ GitHub แสดงในหน้า Pages อย่าคัดลอก URL ตัวอย่างมาใช้เป็น URL จริง
6. ตั้งโดเมนกำหนดเองเป็น `ayeduplan1.thamdee.com` (ไฟล์ `CNAME` ในรากคลังงานมีค่านี้แล้ว) จากนั้นที่ผู้ให้บริการ DNS ของ `thamdee.com` สร้างระเบียน **CNAME** ชื่อโฮสต์ `ayeduplan1` ชี้ไปที่ `<ชื่อบัญชี GitHub ของคุณ>.github.io` ตามที่ GitHub แสดงในหน้า Pages อย่าใส่ชื่อบัญชีสมมติ
7. เมื่อ GitHub ออกใบรับรองแล้ว ให้เปิด **Enforce HTTPS** และทดสอบจาก `https://ayeduplan1.thamdee.com/` รวมลิงก์ดาวน์โหลด ไอคอน และภาพแชร์ `assets/og-image.png`

ขั้นตอนอ้างอิง [คู่มือสร้าง GitHub Pages ของ GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) [การกำหนดแหล่งเผยแพร่](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) และ [โดเมนกำหนดเอง](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) ตรวจอ่าน 13 กันยายน 2569 ทั้งนี้หน้าตาหรือสิทธิของบัญชีอาจเปลี่ยนแปลงได้

## ตั้งค่าพื้นที่แลกเปลี่ยนสาธารณะ (เลือกทำภายหลัง)

ค่าเริ่มต้นใช้ช่องทางอีเมล `burapatis@gmail.com` ได้ทันที แต่ **ไม่มีระบบรับข้อความหรือกระดานแสดงความคิดเห็นในตัว** ผู้ใช้ต้องกดส่งเองในแอปอีเมล

หากต้องการให้ผู้เข้าชมสนทนากันผ่าน GitHub:

1. เปิดคุณสมบัติ Discussions ใน Settings ของคลัง GitHub และตั้งกติกากับผู้ดูแล
2. สร้างหมวดหมู่ตามต้องการ เช่น คำถาม ข้อเสนอข้อมูล บทเรียนจากพื้นที่
3. แก้ไฟล์ `assets/config.js` จาก `discussionsUrl: ''` เป็น URL กระดานจริง เช่นรูปแบบ `https://github.com/ชื่อบัญชี/ชื่อคลัง/discussions` โดยแทนชื่อทั้งหมดด้วยค่าจริง
4. อัปโหลดไฟล์ที่แก้ แล้วทดสอบปุ่มในหน้าแลกเปลี่ยน เว็บยอมรับเฉพาะ HTTPS ของ github.com ที่ลงท้ายด้วยเส้นทาง `/discussions` เท่านั้น

ผู้เข้าร่วมกระดานจะใช้งานตามเงื่อนไขของ GitHub และอาจต้องเข้าสู่ระบบเพื่อร่วมสนทนา อ่าน [วิธีเปิด GitHub Discussions](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/enabling-or-disabling-github-discussions-for-a-repository) ประกอบ ไม่ใส่รหัสผ่านหรือโทเคนใด ๆ ในไฟล์เว็บ

ก่อนเปิดกระดานจริง ควรกำหนดผู้ดูแล วิธีแจ้งเนื้อหาไม่เหมาะสม การซ่อนหรือลบข้อมูลเด็ก และการแจ้งผู้ส่งเมื่อจำเป็นต้องแก้ข้อความ ความเห็นทางอีเมลไม่ควรถูกนำไปเผยแพร่โดยไม่มีการอนุญาต

## วิธีใช้แบบประเมิน

- ใช้คำถาม 12 ข้อชุดเดียวกันก่อนและหลัง ไม่มีรหัสที่สร้างจากวันเกิดหรือโทรศัพท์
- ข้อ 1–10 และ 12 ใช้มาตราความมั่นใจในการอธิบาย/ปฏิบัติ ข้อ 11 ใช้มาตราการเห็นความสำคัญ จึงแสดงแยกกัน
- ค่าเฉลี่ยความมั่นใจ = ผลรวมคะแนนข้อ 1–10 และ 12 ÷ 11
- ผลต่าง = ค่าเฉลี่ยหลัง − ค่าเฉลี่ยก่อน ไม่ใช่ร้อยละการเรียนรู้หรือหลักฐานเชิงสาเหตุ
- เปรียบเทียบเฉพาะเมื่อคำตอบครบทั้งสองช่วง ไม่ใช้ศูนย์แทนข้อมูลที่ขาด
- ปุ่มดูผลไม่บันทึกถาวร กดปุ่มบันทึกบนอุปกรณ์หากต้องการเปลี่ยนหน้าแล้วกลับมาทำต่อ
- ข้อมูลที่บันทึกอยู่ในที่เก็บของเบราว์เซอร์ ไม่มีการส่งคะแนนเข้าฐานข้อมูลกลาง ผู้จัดทำจึงไม่เห็นผลรวมผู้เข้าร่วมจากเว็บไซต์นี้
- ไฟล์ CSV ที่ดาวน์โหลดมีเครื่องหมาย UTF-8 BOM เพื่อช่วยให้โปรแกรมตารางคำนวณอ่านภาษาไทยได้
- แบบออนไลน์ปรับคำและมาตราบางส่วนจากเอกสาร 14 ไม่ควรรวมผลสองฉบับเป็นข้อมูลชุดเดียวโดยไม่ตรวจความเทียบเคียง

สำเนา PPTX สำหรับเผยแพร่เปลี่ยนเฉพาะที่อยู่ไฟล์อ้างอิงในหมายเหตุจากเครื่องเดิมเป็นชื่อไฟล์ `document-XX.md` ในชุดดาวน์โหลด เพื่อไม่เผยแพร่ที่อยู่ไฟล์ส่วนตัว หากดาวน์โหลด PPTX ไปเพียงไฟล์เดียว ให้เปิดเอกสารประกอบจากคลังความรู้บนเว็บ หรือดาวน์โหลดเอกสารที่อ้างถึงไว้ในโฟลเดอร์เดียวกัน ส่วนที่แสดงบนสไลด์และไฟล์ต้นฉบับเดิมไม่ได้เปลี่ยน

## การปรับปรุงเนื้อหา

1. สำรองไฟล์หรือบันทึกรุ่นใน GitHub ก่อนแก้ไข
2. แก้เนื้อหาสรุปได้โดยตรงในไฟล์ HTML ของหน้านั้น รักษาป้ายสถานะข้อเท็จจริง/ข้อเสนอและแหล่งอ้างอิง
3. หากแก้เอกสาร MD ใน `downloads/` ต้องแก้หน้า HTML คู่กันใน `articles/` ด้วย เว็บไซต์ไม่ได้แปลง MD ใหม่ในขณะเปิดอ่าน
4. หากเพิ่มเอกสาร ให้เพิ่มรายการใน `library.html` และ `assets/documents.json` พร้อมไฟล์อ่าน/ดาวน์โหลดที่มีอยู่จริง
5. หากเปลี่ยนส่วนหัว ส่วนท้าย ชื่อผู้จัดทำ หรืออีเมล ให้ปรับให้ตรงกันทุกหน้า รวม `assets/app.js` ซึ่งใช้เตรียมอีเมล
6. หากแก้สไลด์ ให้ปรับ PPTX ภาพสไลด์ และคำบรรยายบนเว็บให้เป็นรุ่นเดียวกัน ภาพชุดนี้เป็นภาพจากสไลด์ที่จัดทำไว้เดิม
7. บันทึกวันที่ เหตุผล ผู้ตรวจ และเอกสารที่ใช้ใน `CHANGELOG.md` อย่าเปลี่ยนวันที่ตัดยอดข้อมูลเพียงเพราะแก้หน้าตาเว็บ
